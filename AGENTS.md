# AGENTS.md

> Точка входа для агентских сессий. Файл — **краткий указатель**: детали и глубина живут в `docs/`.
> Ветка `main`, remote `git@github.com:yatledger/srv.git`.

## 1. Обзор в двух словах

- **Что это:** `dagdb` — распределённый узел хранения DAG-графа транзакций поверх консенсуса Raft
  (Rust edition 2024: tokio, axum, openraft, redb, redis, rayon, ed25519-dalek, blake3).
- **Для кого:** внутренняя команда `yatledger`.
- **Зрелость:** внутренний прототип / R&D. Текущий фокус: **поиск и исправление багов**.
- **Ключевые возможности:** детерминированный state machine, персистентность (redb), публичный HTTP-API +
  внутренний API по токену, метрики Prometheus, rate limit, graceful shutdown, бэкап/restore,
  OpenAPI-спецификация, аудит-логи, профили окружения.

## 2. Документация

Документы лежат в `docs/` — **сканируй папку**, не полагайся на фиксированный список (AGENTS.md
намеренно не перечисляет файлы, чтобы docs можно было дополнять без правок здесь). Каждый документ
помечен в начале: назначение, группа, статус.

- 📁 `docs/` — карта и документация; начни с [`docs/README.md`](docs/README.md).
- 🗂️ `docs/edits/<тип>/<slug>/` — задачи проекта: `audit` | `fix` | `feature`. Новые анализы/багфиксы/
  фичи заводятся новыми папками. Пример: [`docs/edits/audit/big-bang/`](docs/edits/audit/big-bang/) —
  первичный полный аудит (все задачи закрыты; это история).
- 📦 `docs/api/` — публичный API (описание и `openapi.json`).
- 🧠 `.agents/skills/` — методики (скиллы агента).
- 🗄️ `docs/legacy/` — архив мёртвых черновиков исходников (**не собирается, не трогать**).

## 3. Карта кода (кратко; полная — в `README.md` → «Архитектура»)

- Точка входа: `src/main.rs` → `config.rs` (clap + dotenvy) → `lib.rs::start_raft`.
- HTTP: `server.rs` (маршруты/хендлеры), `auth.rs` (токен), `web.rs` (внутрикластерный клиент).
- Домен: `tx_logic.rs` + `utils.rs` (канонический хэш, подпись), `domain.rs`, `graph/{dag,weights}.rs`.
- Raft: `src/raft/` — `command.rs`, `log.rs`, `store.rs`, `db.rs`, `network.rs`, `router.rs`, `api.rs`.
- Эксплуатация: `processor.rs` + `cleanup.rs`, `metrics.rs`, `ratelimit.rs`, `shutdown.rs`, `audit.rs`.
- Тесты: `tests/api/` и `tests/cluster/` (нужен Redis). Бенчмарки: `benches/graph_bench.rs`.

**Поток записи:** `POST /` → `tx_logic` (структура, `func`, `var`, канонический хэш, подпись) →
ранняя проверка состояния → пересылка лидеру → `Raft.client_write` → детерминированный apply на всех репликах.

## 4. Соглашения и стандарты

- **Стиль:** `cargo fmt` (max_width 100, Unix) и `cargo clippy --all-targets -- -D warnings` обязаны быть зелёными.
- **Комментарии/доки:** RU-комментарии, `rustdoc` на публичных API; не оставлять устаревшие комментарии.
- **Именование:** аббревиатуры в CamelCase как слово (`Dag`, `DagVisitor`), не `DAG`.
- **Git:** Conventional Commits (`type(scope): summary`; type ∈ feat/fix/refactor/test/docs/chore/perf/security),
  ссылка на задачу/находку в теле (`Refs: K1`). Ветки `feat/...`, `fix/...`, `security/...`.
  Форматирование/рефактор не смешивать с логикой в одном коммите.
- **Секреты:** только из env/`.env` (в `.gitignore`); в коде и истории git секретов быть не должно.

## 5. Как агенту работать

- **Workflow:** изучай код и стиль перед правками → для крупных/рискованных изменений **сначала выведи
  краткий план и список затрагиваемых файлов и дождись «ок»**. Мелкие безопасные изменения (тесты, доки,
  форматирование, очевидные багфиксы) — самостоятельно.
- **Одна задача = один шаг.** После каждого: `cargo fmt --all`, `cargo clippy --all-targets`, `cargo test --all`
  — всё зелёное. Статусы задач обновляй в трекере соответствующего `docs/edits/<тип>/<slug>/` отдельным `docs:` коммитом.
- **Тесты:** обязателен полный прогон `cargo test --all`. Интеграционные (`tests/api`, `tests/cluster`)
  требуют Redis — подними его (`docker run -d -p 6379:6379 redis:7-alpine`) или явно предупреди, что он недоступен.
- **В конце сессии — отчёт:** выполненные задачи, изменённые файлы, результаты проверок, отклонения, что дальше.
- **Нельзя без явного разрешения:** коммитить `.env`; ослаблять правила CI/clippy; удалять или переписывать
  незакоммиченные/чужие изменения; трогать `docs/legacy/`; менять формат `genesis.json`.

## 6. Инварианты (критичные зоны — не ломать без разрешения)

- **Канонический хэш и подпись** (`utils.rs`, `tx_logic.rs`): `func` входит в хэш; ключи сортируются
  рекурсивно; одинаковый контент → одинаковый хэш на всех репликах.
- **Детерминированный state machine и персистентность** (`raft/store.rs`, `raft/db.rs`, `raft/log.rs`):
  одинаковая команда → одинаковое состояние; валидация не зависит от сети/времени.
- **`added` и уникальность хэша** (`graph/dag.rs`): удалённые узлы попадают в `added` и переживают
  снапшот/рестарт; повторная вставка запрещена.
- **Разделение публичного и внутреннего API** (`auth.rs`, `server.rs`): `/`, `/pool`, `/full` публичны;
  `/add`, `/remove_heavy_nodes`, `/load-genesis`, `/raft/*`, `/mng/*` — только с `x-internal-token`.
- **Контракт Raft-типов/команд** (`raft/command.rs`, `raft/mod.rs::typ`): совместимость лога и снапшотов.

## 7. Подводные камни

- **Внутрикластерный трафик без TLS** — защищён общим `INTERNAL_API_TOKEN`; TLS осознанно вне скоупа.
- **`validate_parents` (2..100) — только на границе API**, не в state machine: генезис-узлы легитимно без родителей.
- **`StateMachineStore::default()` — in-memory** (тесты, openraft Suite); персистентный режим — только `open(path)`.
- **Схема состояния версионируется** (`SCHEMA_VERSION`): версия «из будущего» отклоняется, старые снапшоты
  мигрируют. При смене формата — поднимай версию и добавляй миграцию.
- **`added` ограничен** `MAX_ADDED_ENTRIES`, вытеснение детерминировано; номер удаления монотонный (не часы).
- **`genesis.json`** содержит узлы с пустыми `addr`/`sign` и пустыми `prnts` — норма для bootstrap.
- **Метрики и rate limiter — в памяти узла**; **Redis обязателен** для очистки и интеграционных тестов.

## 8. Быстрый старт

```bash
cargo build --release        # или ./build.sh → target/release/dagdb
cp .env.example .env         # обязательны REDIS_URL и INTERNAL_API_TOKEN

docker compose up --build    # кластер node1..node4 (21001..21004) + Redis
# либо: docker run -d --name dagdb-redis -p 6379:6379 redis:7-alpine + запуск узлов вручную (README.md), затем ./test.sh

cargo fmt --all && cargo clippy --all-targets && cargo test --all
cargo bench --no-run         # проверка компиляции бенчмарков

./scripts/backup.sh          # снапшот + DATA_DIR + дамп Redis
./scripts/restore.sh         # узел должен быть остановлен
```
