# ТЗ №1. Критический уровень 🔴

> Характер проблем: ломают безопасность, целостность и сохранность данных, приводят к падению узлов.
> Без выполнения этого блока проект нельзя запускать ни в одном окружении, кроме локальной песочницы.

## 1. Цель

Устранить проблемы, которые ломают безопасность, целостность и сохранность данных, а также приводят к падению узлов.

## 3. Технические требования

- **K1**: убрать пароль Redis из `src/lib.rs:77` и из `to/*.rs`; параметры `REDIS_URL`, `BIND_ADDR`, `HTTP_PORT`, `DATA_DIR`, таймауты читать из env (через `clap`/`dotenvy`); **использовать уже добавленный `.env.example`** (при необходимости дополнить переменные) и убедиться, что `.env` в `.gitignore`; **ротировать скомпрометированный пароль** и удалить его из истории git (BFG/`git filter-repo`).
- **K2**: `func` включать в хэшируемый/подписываемый контент; заменить конкатенацию без разделителей в `src/utils.rs` (`process_value`) на каноничную сериализацию (стабильный JSON/CBOR целиком); в `src/graph/dag.rs:61` убрать `.unwrap()` → возвращать `Result`; валидировать структуру `var` (`TxVar`) **до** `client_write`.
- **K3**: разделить API на публичный (`/`, `/pool`, `/full`) и внутренний; для `/add`, `/raft/*`, `/mng/*` ввести аутентификацию (кластерный токен/подпись узла); `add_handler` (`src/server.rs:218`) обязан проходить те же проверки, что `add_tx`, либо не быть доступным извне.
- **K4**: в `src/raft/store.rs` заменить `parents_exist = true` (`:132`) и `nodes_exist = true` (`:149`) на детерминированные проверки: существование и уникальность родителей, отсутствие дубликата узла, допустимость `func`/`var`; проверки идентичны на всех репликах и не зависят от сети.
- **K5**: реализовать персистентные `RaftLogStorage`/`RaftStateMachine` (RocksDB/sled/redb) с сохранением vote, committed, логов, снапшотов; путь — из `DATA_DIR`; in-memory оставить только для тестов.
- **K6**: unit-тесты на `ordered_sum` (в т.ч. негативные: подмена `func`, коллизии), `validate_parents`, `DAG::add/remove`, валидацию `var`; интеграционный тест записи/восстановления состояния.
- **K7**: README описывает назначение, стек, архитектуру, сборку, запуск кластера (из 4 узлов + Redis), env-переменные, примеры API.

## 4. Критерии готовности (Definition of Done)

- Ни одного секрета в репозитории и в истории git; запуск воспроизводится из `.env.example`.
- Подпись и хэш невозможно обойти подменой `func`/структуры `var`; узловая паника на вредоносной транзакции невоспроизводима.
- Внешний клиент не может влиять на Raft/membership и не может вставить узел мимо валидации.
- Остановка и рестарт узла сохраняют журнал и DAG; кластер продолжает работу.
- `cargo test` покрывает критические сценарии и зелёный в CI.
