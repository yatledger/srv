# ТЗ №2. Важный уровень 🟠

> Характер проблем: серьёзные недочёты, мешающие корректной и предсказуемой работе кластера и сопровождению.

## 1. Цель

Устранить серьёзные недочёты, мешающие корректной и предсказуемой работе кластера, и подготовить проект к сопровождению.

## 2. Задачи и приоритеты

| ID | Задача | Приоритет |

## 3. Технические требования

- **V1**: `DAG::serialize` (`src/graph/dag.rs:302`) должен сохранять `added`; задать политику очистки `added` (TTL/лимит), согласовать с проверкой родителей `src/server.rs:133`.
- **V2**: убрать `continue` для лидера в `src/processor.rs:31` (или явно назначить роль обработчика); прекратить клонирование всего DAG каждые 250 мс; пересмотреть формулу веса/порог (`src/graph/weights.rs:23`).
- **V3**: использовать глобальный rayon-пул вместо `ThreadPoolBuilder::new()` на каждый вызов (`weights.rs:52`); добавить мемоизацию (перенести из `to/weights.arc.rs`).
- **V4**: перенести проверки зависимостей на момент применения у лидера либо использовать linearizable-read перед постановкой в Raft.
- **V5**: свести `src/web.rs::Router` и `src/raft/router.rs::Router` к одному клиенту; зафиксировать единый JSON-контракт (убрать «три стратегии парсинга» `raft/router.rs:134-168`).
- **V6**: вынести HTTP-хендлеры/валидацию/Redis из `server.rs`; `transferToken` вынести из `dag.rs:59` в слой логики.
- **V7**: заменить рантайм `unwrap/expect` (19 шт.), ввести `thiserror`-тип (+ опционально `anyhow` на границе); `ApiRouterError` реализовать `Display`/`Error`.
- **V8**: `start_server` использует переданный `addr`, а не хардкод `0.0.0.0`; внутрикластерный обмен — TLS или подписанные запросы.
- **V9**: добавить `LICENSE`; GitHub Actions: `fmt --check`, `clippy -D warnings`, `test`, `build`; зафиксировать ревизию `openraft` и версии зависимостей.
- **V10**: `///`-документация публичных API; исправить неверные комментарии (`server.rs:16`, `utils.rs:52`); единый язык комментариев.

## 4. Критерии готовности (Definition of Done)

- Снапшот/восстановление сохраняет `added`; память под `added` ограничена.
- Очистка «тяжёлых» узлов работает и в одноузловом кластере; нет периодического клонирования всего DAG.
- Нагрузочный обход графа не создаёт пул потоков на каждый вызов.
- В публичных хендлерах нет потенциальных паник; ошибки возвращаются типизированно.
- CI зелёный; лицензия присутствует; зависимости воспроизводимы.
