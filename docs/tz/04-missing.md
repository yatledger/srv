# ТЗ №4. Отсутствует важное 🔵

> Характер проблем: важные компоненты, которых сейчас нет, но без которых система не готова к реальной эксплуатации.

## 1. Цель

Добавить компоненты, которых сейчас нет: тестирование, наблюдаемость, защита от злоупотреблений, спецификация, восстановление.

## 2. Задачи и приоритеты

| ID | Задача | Приоритет |
|----|--------|-----------|
| O1 | Полноценный набор тестов: unit + integration + cluster | P1 |
| O2 | Наблюдаемость: метрики, healthcheck/readiness | P2 |
| O3 | Rate limiting и квоты на публичные эндпоинты | P2 |
| O4 | Спецификация API и формата транзакции | P2 |
| O5 | Graceful shutdown, бэкап и восстановление | P2 |
| O6 | Версионирование состояния/снапшотов и миграции | P3 |
| O7 | Аудит-логирование значимых операций | P3 |
| O8 | Конфигурация под окружения (dev/stage/prod) | P3 |
| O9 | Бенчмарки производительности графа | P4 |

## 3. Технические требования

- **O1**: наполнить пустой `tests/cluster/test_cluster.rs`; сценарии: инициализация, add-learner, change-membership, репликация, снапшот, рестарт узла, конкурентные записи; отдельные интеграционные тесты HTTP API.
- **O2**: экспорт метрик Raft + DAG (узлы, вес, очередь, latency) в Prometheus; `/health` и `/ready`; структурированные логи (JSON) с корреляционным id.
- **O3**: ограничение частоты запросов на `/` и advisory-лимиты размера `Tx`.
- **O4**: OpenAPI/Swagger для публичного API; документированная схема `Tx`/`var`/`func` и правил валидации.
- **O5**: корректная остановка (`with_graceful_shutdown`) с финализацией Raft; процедура бэкапа/восстановления данных и Redis-архива.
- **O6**: поле версии схемы состояния; стратегия миграций снапшотов при изменении формата.
- **O7**: audit-log записей add/remove/membership с указанием источника.
- **O8**: профили конфигурации, валидация обязательных env при старте с понятными ошибками.
- **O9**: criterion-бенчмарки на `compute_descendants_with_depth_and_weight`, `get_nodes_by_depth`, throughput записи.

## 4. Критерии готовности (Definition of Done)

- Кластерный тест поднимает минимум 3 узла, проверяет репликацию, рестарт и снапшот в CI.
- Есть `/metrics`, `/health`, `/ready`; метрики собираются внешней системой.
- Публичный API ограничен по частоте и описан спецификацией.
- Узел корректно завершается без потери состояния; есть проверенный сценарий восстановления.
- Зафиксированы базовые числа производительности графа.

## 5. Порядок реализации

O1 → O5 → O2 → O4 → O3 → O7 → O8 → O6 → O9.
