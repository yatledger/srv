# N03 — план реализации наглядного вывода `loadgen`

> Группа: **edits/feature/loadgen-live-output** · Тип: **feature** · Статус: ✅ **выполнено**.
> Сопутствующие документы: [`spec.md`](spec.md) (ТЗ), [`tracker.md`](tracker.md), [`report.md`](report.md).
> Регламент: [`AGENTS.md`](../../../../AGENTS.md) · формат фич: [`../README.md`](../README.md).
> Коммит-база: `af6aa49`. Реализация — отдельной сессией после согласования.

## 1. Цель и границы

Добавить в рантайм-инструмент `loadgen` (N01) **наглядный пофреймовый вывод** запроса/ответа и
настраиваемую **паузу между запросами** (`--sleep`), включая авто-демо-режим «без параметров»
(случайная пауза `0.1..2.5` с, `concurrency = 1`, TPS выключен). Изменения аддитивны и не влияют на
корректностные инварианты, код возврата, `--json-out`, CI и публичный API.

Границы и не-цели — см. [`spec.md`](spec.md) §4.

## 2. Требования к поведению после реализации

См. R1–R8 в [`spec.md`](spec.md) §3. Кратко:

| Ситуация | `show_tx` | пауза | TPS | concurrency | бюджет |
|---|---|---|---|---|---|
| без аргументов | ✅ вкл | random `0.1..2.5` с | 0 (выкл) | 1 | `--duration-sec 60` |
| `--show-tx` | ✅ вкл | по `--sleep` (иначе нет) | по `--tps` | по флагу/дефолту 8 | `--tx` (дефолт 500) |
| `--sleep N` | ❌ выкл | фикс `N` с (`0` — выкл) | по `--tps` | по дефолту 8 | `--tx` (дефолт 500) |
| `--json-out …` (как в CI) | ❌ выкл | нет | по `--tps` | по дефолту 8 | `--tx` (дефолт 500) |

## 4. Шаги реализации

Порядок — по этапам с независимой проверкой. Один коммит = один логически завершённый шаг
(Conventional Commits, `Refs: N03`). Форматирование/рефакторинг не смешивать с логикой.

### Этап 1 — CLI и пейсинг

1. `main.rs`: добавить флаги:
   - `--show-tx` (`bool`, по умолчанию `false`);
   - `--sleep <SECS>` (`Option<f64>`; `0` допустим, отрицательные/`NaN` — ошибка валидации clap
     `value_parser`).
2. Детект **«без аргументов»**: `std::env::args_os().len() == 1`. Резолвинг демо-дефолтов в
   `LoadgenConfig` (методы или поля, вычисляемые в `run`):
   - демо: `show_tx = true`, `sleep = Sleep::Random(0.1, 2.5)`, `tps = 0`, `concurrency = 1`,
     `duration_sec = Some(60)`, `tx = None` (бюджет — по времени);
   - иначе: `show_tx` — из флага; `sleep` — `Some(N)`/`None`; `tps` — из `--tps` (дефолт 500);
     `concurrency` — из `--concurrency` (дефолт 8); бюджет — из `--tx`/`--duration-sec` как сейчас.
3. `runner.rs`: заменить `interval` на модель пейсинга:
   ```rust
   /// Модель пейсинга между запросами.
   enum Pacing {
       /// Целевой суммарный TPS (per-worker = tps/workers).
       Tps(Duration),
       /// Фиксированная пауза.
       Fixed(Duration),
       /// Пауза отсутствует (максимальная скорость) — `--sleep 0`/`--tps 0` без паузы.
       None,
       /// Случайная пауза `[min, max]` (демо-режим).
       Jitter { min: f64, max: f64 },
   }
   ```
   Пауза `Jitter` разыгрывается **отдельным** `Prng` на воркер (seed из `worker_id`), чтобы не
   сдвигать поток параметров транзакций (см. `spec.md` §3.2, детерминизм).
4. Семантика:
   - демо (`tps = 0`, `sleep = random`) → `Jitter`;
   - `--sleep 0` → `None` (паузы нет);
   - `--sleep N>0` → `Fixed`;
   - `--tps > 0` без `--sleep` → `Tps` (прежнее поведение);
   - `--tps > 0` **и** `--sleep N>0` → оба (`Tps` + `Fixed`) — осознанное сочетание пользователя.

### Этап 2 — сбор информации и рендер блока

5. `runner.rs`: расширить внутреннюю структуру результата попытки, чтобы рендер имел всё нужное:
   - `status: u16`, `latency_ms: f64`, `reason: Option<String>`, `transport_error: bool`
     (уже есть в `ClientOutcome`);
   - добавить `attempts: u32` (число попыток) и краткое infо о транзакции (`seq`, `addr`, `prnts`,
     `func`, `sign`) — либо рендерить прямо из `&SignedTx` в момент ответа.
6. `report.rs`: вынести рендерер блока с чистыми функциями, **без побочного ввода-вывода** (возвращают
   `String`), чтобы юнит-тестировать:
   - `fn format_request_line(n: u64, worker: usize, signed: &SignedTx, leader: &str) -> String`;
   - `fn format_response_line(status: u16, latency_ms: f64, reason: Option<&str>) -> String`;
   - `fn render_frame(...) -> String` — собирает весь блок с рамкой и цветами.
   Функции принимают `&Palette` (вкл/выкл ANSI). Точный вид — образец ниже (§4.1).
7. Вывод в `runner.rs`: общий `Arc<Mutex<()>>` (или `tokio::sync::Mutex`) вокруг `print!`/`println!`,
   чтобы блоки не перемешивались при `concurrency > 1` (R6). В демо-режиме `concurrency = 1`, так что
   мьютекс — просто гарантия.
8. Ретраи: печатать только **финальную** попытку (R7); промежуточные — в `--verbose` (`eprintln!`).

### 4.1. Образец блока (черновой; уточняется при реализации)

```
┌─ #12 · worker 0 · seq 12 · addr 7Qk…3fA ─────────────────────────────
│ → POST http://127.0.0.1:21001/   func=transferToken
│   prnts[2] 9c1…a2b, 4de…0f7
│   var {to: Bm8…qL2, val: 48215, msg: "hello"}  sign: 3ab…c9d
│ ← 200 OK · 14.7 ms
└──────────────────────────────────────────────────────────────────────
```

Отказ (`4xx`) — красная строка ответа с причиной (`message` из `ApiResponse`); `5xx`/транспорт — с
пометкой. Цвета: зелёный `200`, красный отказ, приглушённые рамка/шапка.

## 5. Тесты

- **Юнит-тесты** (`#[cfg(test)]`):
  - `format_request_line`/`render_frame`: содержат номер, `seq`, статус и задержку; ANSI
    присутствует при включённой палитре и отсутствует при выключенной;
  - резолвинг демо-дефолтов: «без аргументов» ⇒ `show_tx=true`, `jitter 0.1..2.5`, `tps=0`,
    `concurrency=1`, `duration_sec=Some(60)`; набор аргументов ⇒ демо выключен;
  - `--sleep 0` ⇒ паузы нет; `--sleep 1.5` ⇒ `Fixed(1.5)`; валидация отрицательного/`NaN` — ошибка;
  - `Prng`/`range_f64`: значения в границах `[0.1, 2.5]`, детерминизм при одном seed.
- **Без добавления** нагрузочных тестов в `cargo test --all` (решение по N01 в силе).
- `cargo fmt --all`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all` — зелёные
  (Redis — для интеграционных `tests/api`/`tests/cluster`).
- **Ручная проверка:** прогон `loadgen` с Redis и без параметров (визуально), плюс `--show-tx
  --sleep 0 --tx 30` (быстрый прогон с выводом) и `--json-out` (без блоков).

## 7. DoD

- `loadgen` **без аргументов** печатает наглядные цветные блоки запрос/ответ, идёт медленно
  (случайная пауза `0.1..2.5` с), `concurrency = 1`, TPS не ограничивает, длительность `~60 с`;
- `--show-tx` включает вывод при явных прочих флагах; `--sleep 0` убирает паузу;
  `--sleep N` задаёт фиксированную паузу; цвета включаются только на TTY и учитывают `NO_COLOR`;
- `--json-out` и CI-прогон **не** печатают блоки и не замедляются;
- корректностные инварианты/код возврата прежние (приняты все валидные tx, реплики совпадают);
- `cargo fmt --all`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all` — зелёные
  (Redis для интеграционных; при отсутствии — сообщено явно);
- инварианты `AGENTS.md` §6 не нарушены; `SCHEMA_VERSION`/Raft-контракт/публичный API не менялись;
- новых зависимостей нет; `README.md` и `docs/edits/feature/` обновлены.

## 8. Риски и откат

| Риск | Митигация |
|---|---|
| Перемешивание вывода при `concurrency>1` | общий мьютекс на печать целого блока; демо-режим `concurrency=1` |
| Сдвиг детерминированного потока tx из-за случайной паузы | пауза на **отдельном** ГПСЧ; параметры tx не зависят от паузы |
| Замедление/шум в CI или при `--json-out` | авто-демо только при полном отсутствии аргументов; явные флаги сохраняют прежнее поведение |
| Некорректные ANSI/странные символы в не-TTY или логах | авто-детект TTY, поддержка `NO_COLOR`, текстовый fallback без ESC |
| Долгий прогон без параметров (пауза до 2.5 с) | демо ограничено по времени `--duration-sec 60` (~1 мин) |
| Флаг `--sleep` конфликтует с `--tps` | ортогональны: в демо TPS выключен; при явных обоих — осознанное сочетание |
| Новый код ломает clippy/сборку | полная проверка `clippy --all-targets`; новые функции — с `rustdoc` |

**Откат:** изменения аддитивны (флаги + рендер + README). Удаление флагов/кода возвращает прежнее
поведение; данные/схема не затрагиваются, миграция не нужна. Точка отката — `af6aa49`.
