# План устранения: случайный узел-приёмник `loadgen` (F4)

> Группа: **edits/fix/loadgen-forward-to-leader** · Тип: **fix** · Статус: **реализован, проверки
> пройдены (см. [`report.md`](report.md))**.
> Решение владельца (2026-10-09): случайный узел на **все** прогоны; родители из `/pool` целевого
> узла; в выводе узел и роль.
> Ссылки: [`defect.md`](defect.md) (паспорт дефекта), [`tracker.md`](tracker.md), [`report.md`](report.md).

## 1. Цель и границы

**Чиним.** Нагрузочный клиент должен обращаться к **любому** узлу кластера (случайно), как реальный
клиент, а не только к лидеру, сохраняя корректностную проверку и наглядный вывод.

**В скоупе:**
- `src/bin/loadgen/runner.rs` — случайный выбор узла на каждый запрос; кэш `/pool` отдельно на каждый
  узел; отдельный ГПСЧ выбора узла; `resolve_leader` возвращает id лидера; роль узла.
- `src/bin/loadgen/report.rs` — в строке запроса узел и роль (`format_request_lines`, `render_frame`).
- `README.md` — описание случайного узла-приёмника и форвардинга.
- Тесты (`runner.rs`, `report.rs`).

**Вне скоупа (осознанно):**
- Изменения серверного форвардинга (`server.rs`) — он уже реализован и лишь начинает покрываться.
- Изменения state machine, Raft-контракта, канонического хэша/подписи, `SCHEMA_VERSION`, публичного/
  внутреннего API, `Cargo.toml`.

## 2. Требования к поведению после фикса

1. Каждый запрос адресуется случайному узлу из `nodes` (не обязательно лидеру).
2. Не-лидер перенаправляет запись лидеру (существующий `server.rs::add_tx`).
3. Родители берутся из `/pool` **того же узла**, которому шлём, — ранняя проверка
   (`validate_against_state`) не отклоняет валидную tx из-за отставания реплики.
4. В пофреймовом выводе: `→ POST http://host:port (лидер|follower → лидер)   func=…`.
5. Детерминизм параметров транзакций при одном `--seed` сохраняется (выбор узла и пауза — отдельные
   ГПСЧ).
6. Корректностные инварианты и код возврата прежние: все валидные tx приняты, размеры DAG совпадают.

## 4. Шаги реализации (порядок)

1. `runner.rs`: заменить `leader: &str` на `nodes: &[(u64, String)]` + `leader_id: u64`; в
   `run_load` клонировать `nodes` в каждую задачу; `resolve_leader` вернуть id лидера.
2. `runner.rs`: в `worker_loop` завести `node_rng` (отдельный seed) и `pools` на каждый узел; на
   итерации выбирать узел, рефрешить/брать его `/pool`, строить tx и POSТить на него.
3. `runner.rs`: `node_role(node_id, leader_id)`; передать роль в `render_frame`.
4. `report.rs`: добавить параметр `role` в `format_request_lines`/`render_frame`.
5. Тесты: `node_role_distinguishes_leader_and_forward`, `node_pick_is_bounded_and_deterministic`;
   обновить тесты рендера под новую сигнатуру.
6. `README.md`: описать поведение и вывод.
7. Проверки: `cargo fmt --all`, `clippy --all-targets -- -D warnings`, `test --all` (Redis),
   ручные прогоны.

## 5. Тесты

- **Модульные.** `node_role` (лидер/форвард); выбор узла — в границах `[0, nodes)` и детерминирован
  при одном `node_seed`; рендер содержит узел и роль, без ANSI при выключенной палитре.
- **Регрессионный (обязателен).** Поведенческий: прогон со случайными узлами даёт **все** запросы
  принятыми (`accepted == attempted`) и равные размеры DAG по репликам. Проверяется ручными прогонами
  (§4.1 в `report.md`), т.к. требует in-process кластера + Redis.
- **Интеграционные.** `tests/api`/`tests/cluster` не затронуты.

## 6. Definition of Done

- [x] Запросы уходят на случайный узел; не-лидер форвардит лидеру.
- [x] Родители берутся из `/pool` целевого узла; ложных `409` нет.
- [x] Вывод показывает узел и роль.
- [x] `cargo fmt --all` / `clippy --all-targets -- -D warnings` / `test --all` — зелёные.
- [x] Ручные прогоны: `--tx 40 --concurrency 4` → 40/40 и все узлы; `--tx 300 --concurrency 8` → 300/300,
      реплики равны.
- [x] Инварианты (`AGENTS.md` §6) не затронуты; `SCHEMA_VERSION` не менялся.

## 7. Риски и откат

| Риск | Митигация |
|---|---|
| Ложные `409` из-за отставания follower | Родители из `/pool` **того же** узла (ключевое решение). |
| Падение TPS/рост задержки из-за хопа форварда | Отмечено как ожидаемое; метрики информационные, не SLA. |
| Сдвиг детерминированного потока tx | Выбор узла — отдельный ГПСЧ (`node_seed`). |
| Шум в выводе/смешение блоков | Общий мьютекс вывода сохранён (N03). |

**Откат.** Правка локальна (`runner.rs`, `report.rs`, docs); откат — `git revert`. Миграции
состояния/`SCHEMA_VERSION` не требуются.
