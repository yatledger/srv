# edits/fix/

Исправления багов. Формат: `fix/<slug>/`.

Для каждой задачи создавай папку `fix/<slug>/` с описанием дефекта, причиной, планом исправления и
отчётом (что изменено, какие проверки пройдены). Документы помечай в начале: группа, тип, статус.
Методику разбора дефекта и подготовки плана см. в скилле
[`.agents/skills/fix/`](../../../.agents/skills/fix/).

## Задачи

- [`redis-startup-hang/`](redis-startup-hang/) — **F1**: узел зависает на старте при недоступном/неверном
  Redis (HTTP-порт не открывается, redb-lock удерживается). Статус: реализован, проверки пройдены
  (см. `report.md`).
- [`http-port-ignored/`](http-port-ignored/) — **F2**: `HTTP_PORT`/`--port` молча перекрывается
  `BIND_ADDR` из `.env` (локальный мульти-узловой запуск открывает `21001`). Статус: реализован,
  проверки пройдены (см. `report.md`).
- [`cluster-concurrent-seq/`](cluster-concurrent-seq/) — **F3**: кластерный тест падал на шаге
  конкурентной записи (`400`, «non-monotonic seq»): параллельные транзакции одного адреса применялись
  не по порядку, а V18 требует строго возрастающий `seq`. Регрессия V18 (`6f75117`). Статус:
  реализован (шаг 7 переведён на разные аккаунты; docs уточнены), проверки пройдены (см. `report.md`).
- [`loadgen-forward-to-leader/`](loadgen-forward-to-leader/) — **F4**: `loadgen` слал нагрузку строго
  лидеру, минуя форвардинг через follower (публичный путь клиента не проверялся). Статус: реализован
  (случайный узел-приёмник + per-node `/pool`, роль узла в выводе), проверки пройдены (см. `report.md`).
- [`raft-router-unreachable-logs/`](raft-router-unreachable-logs/) — **F5**: Raft-роутер логировал
  штатную недоступность пира (`/raft/append`) как `ERROR`, засоряя вывод в конце нагрузочного прогона.
  Статус: реализован (транспортная ошибка RPC → `debug`), проверки пройдены (см. `report.md`).
- [`loadgen-redis-container/`](loadgen-redis-container/) — **F6**: `scripts/loadgen.sh` не поднимал
  Redis и падал при повторном запуске контейнера (конфликт имени). Статус: реализован (скрипт сам
  поднимает Redis при недоступности, `docker rm -f` перед `run`, пароль из `REDIS_URL`), проверки
  пройдены (см. `report.md`).
