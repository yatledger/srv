# План устранения: Redis в `scripts/loadgen.sh` (F6)

> Группа: **edits/fix/loadgen-redis-container** · Тип: **fix** · Статус: **реализован, проверки
> пройдены (см. [`report.md`](report.md))**.
> Решение владельца (2026-10-09): поднимать Redis только если недоступен; пароль — из `REDIS_URL`.
> Ссылки: [`defect.md`](defect.md), [`tracker.md`](tracker.md), [`report.md`](report.md).

## 1. Цель и границы

**Чиним.** `scripts/loadgen.sh` должен сам обеспечивать доступность Redis, быть идемпотентным при
повторных запусках и брать пароль из единственного источника — `REDIS_URL` (`.env`).

**В скоупе:**
- `scripts/loadgen.sh` — чтение `REDIS_URL` из окружения/`.env`; разбор host/port/password; проверка
  доступности; при недоступности — `docker rm -f` + `docker run` с `--requirepass` (если пароль есть),
  ожидание готовности; маскирование пароля в выводе.

**Вне скоупа:**
- Изменения `docker-compose.yml`, `.env.example`, `Cargo.toml`, ядра.
- Автозапуск Redis для `test.sh`/CI (отдельно, при необходимости).
- Поддержка нестандартных схем Redis (sentinel/cluster/TLS `rediss://`).

## 2. Требования к поведению

1. `REDIS_URL` — из окружения, иначе из `.env`, иначе дефолт `redis://127.0.0.1:6379/0`;
   экспортируется в `loadgen`.
2. Если Redis отвечает — контейнер не трогаем.
3. Если не отвечает — `docker rm -f "$REDIS_CONTAINER"` (ошибка при отсутствии подавляется) и
   `docker run -d --name … -p "${port}:6379" redis:7-alpine [redis-server --requirepass <password>]`.
4. Пароль — из userinfo `REDIS_URL` (`user:password`/`:password`); при отсутствии — Redis без пароля.
5. Готовность — ожидание (опрос), затем продолжение.
6. Пароль не печатается в выводе (URL в сообщениях маскируется).
7. Удалённый хост в `REDIS_URL` — контейнер не поднимаем, честная ошибка.

## 4. Шаги реализации

1. Хелпер `read_env_var` (значение из `.env`, приоритет окружения).
2. Разбор `REDIS_URL`: `hostport`, `userinfo`, `host`, `port`, `password`; строка с маской.
3. `redis_available`: `redis-cli ping`, иначе — `docker inspect` для нашего контейнера (на машинах без
   `redis-cli`).
4. При недоступности: проверка docker/локальности хоста; `docker rm -f`; сборка `docker run`;
   ожидание готовности.
5. Проверки: синтаксис `bash -n`, ручные прогоны (Redis есть/остановлен), `fmt`/`clippy`/`test`.

## 5. Тесты

- Автотестов нет (shell-скрипт). Проверка — ручная: (а) Redis работает → «доступен», контейнер не
  трогается; (б) Redis остановлен → пересоздаётся с паролем из `REDIS_URL`, прогон зелёный;
  (в) пароль не виден в выводе. `bash -n` — синтаксис.
- Регрессионный критерий: повторный запуск не падает на конфликте имени контейнера.

## 6. Definition of Done

- [x] Скрипт поднимает Redis при недоступности; повторный запуск идемпотентен (`rm -f` перед `run`).
- [x] Пароль берётся из `REDIS_URL` и передаётся в `--requirepass`; виден в контейнере.
- [x] Пароль не печатается (маскирование).
- [x] `bash -n` — OK; `fmt`/`clippy`/`test --all` — зелёные; ручные прогоны успешны.

## 7. Риски и откат

| Риск | Митигация |
|---|---|
| `docker rm -f` удалит данные чужого/полезного контейнера | Удаляем только контейнер с нашим именем; имя настраиваемо `REDIS_CONTAINER` |
| Порт занят другим Redis | `docker run` с проверкой кода возврата; понятная ошибка |
| Нет `redis-cli` | fallback `docker inspect` для определения доступности; `loadgen` — fail-fast по Redis |
| Пароль в логах | маскирование строки подключения в сообщениях |

**Откат:** правка локальна (shell); `git revert`. Миграция не требуется.
