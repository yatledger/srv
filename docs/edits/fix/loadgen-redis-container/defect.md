## 2. Симптом и ожидание

Дословная формулировка владельца:

> «давай как-то придумает как запускать редис
> `docker run -d --name dagdb-redis -p 6379:6379 redis:7-alpine \ redis-server --requirepass "$REDIS_PASSWORD"`
> прямо в scripts/loadgen.sh … при повторном запуске будет ошибка
> `docker: Error response from daemon: Conflict. The container name "/dagdb-redis" is already in use …`
> поэтому надо предварительно делать `docker rm -f dagdb-redis` … вопрос в том как передать $REDIS_PASSWORD»

**Наблюдаемое.** `scripts/loadgen.sh` лишь **проверяет** доступность Redis и при отсутствии просит
запустить его вручную. При попытке поднять контейнер повторно Docker падает на конфликте имени.

**Ожидаемое.** Скрипт сам обеспечивает доступность Redis: если Redis уже отвечает — работает как есть;
если нет — снимает одноимённый контейнер (`docker rm -f`) и поднимает свежий, передавая пароль из
`REDIS_URL` (`.`env`), после чего дожидается готовности.

## 3. Анализ причины

1. `scripts/loadgen.sh` (до правки) — только проверка (`redis-cli -u "$REDIS_URL" ping`) и подсказка
   запустить Redis вручную; контейнер не поднимается.
2. Ручная команда владельца не идемпотентна: `docker run --name dagdb-redis` падает, если контейнер с
   таким именем уже существует (в т.ч. **остановленный** — имя занято).
3. Пароль `--requirepass` должен совпадать со строкой подключения `loadgen`; единственный источник в
   проекте — `REDIS_URL` (`redis://[user]:password@host:port/db`), см. `.env.example`/README/`docker-compose.yml`
   (`REDIS_URL: "redis://:${REDIS_PASSWORD}@…"`). Отдельной переменной `REDIS_PASSWORD` в проекте нет.

**Корневая причина (формулировка).** Скрипт-обёртка не управляет жизненным циклом Redis, а ручной
запуск не идемпотентен; кроме того, неочевидно, откуда брать пароль. Решение — управлять контейнером
в скрипте (идемпотентно) и выводить пароль из `REDIS_URL`.

**Регрессия?** Нет; скрипт изначально был «проверяющим».

## 4. Влияние

- **Удобство/эксплуатация (🟡).** Запуск прогона не требует ручных шагов; повторные запуски не падают.
- **Секреты.** Пароль не печатается в stdout (маскируется в сообщениях) — согласуется с политикой
  проекта (не логировать секреты). `REDIS_URL` экспортируется в `loadgen`, не логируется.
- **Корректность/данные.** Не затрагивается; Redis-содержимое пересоздаётся только при недоступности.
- **Инварианты.** Не затрагивает канонический хэш/подпись, state machine, `SCHEMA_VERSION`, Raft-контракт,
  API.
