## 1. Цель и границы

**Чиним.** Недоступность пира при Raft RPC — штатная ситуация; она не должна логироваться как
`ERROR`. Уровень понижается до `debug`, текст сообщения уточняется (узел/URL/причина).

**В скоупе:**
- `src/raft/router.rs` — `error!` → `debug!` для транспортной ошибки `post_text` (клиентская ветка
  `self.http.post_text(...).await.map_err(...)`).

**Вне скоупа (осознанно):**
- Уровни прочих веток роутера (не-2xx HTTP, пустой ответ, ошибка парсинга) — это не «недоступность
  пира», а нарушения контракта RPC; оставлены как есть.
- Серверный форвардинг (`server.rs`), `openraft`, state machine, Raft-контракт, `SCHEMA_VERSION`.

## 2. Требования к поведению после фикса

1. Транспортная недоступность пира при Raft RPC не пишется на уровне `ERROR`.
2. Диагностика остаётся доступной на `debug` (узел, URL, причина).
3. Поведенческий контракт `Unreachable` не меняется — Raft по-прежнему ретраит/перевыбирает лидера.
4. Обычный прогон `loadgen` (в т.ч. с дефолтным уровнем `error`) не содержит этих строк.

## 4. Шаги реализации (порядок)

1. Заменить `error!("Failed to send request to …")` на `debug!("raft rpc to [{}] {} unreachable: {}", …)`.
2. Проверки: `cargo fmt --all`, `clippy --all-targets -- -D warnings`, `test --all`.
3. Ручная проверка: прогон `loadgen` (несколько раз) — строк нет; при `RUST_LOG=debug` диагностика
   присутствует (при реальной недоступности).

## 5. Тесты

- Отдельного юнит-теста на уровень лога нет (проверка уровня логирования хрупка). Контракт
  `Unreachable` покрыт существующими тестами `web.rs`/`tests`; поведение не изменилось.
- **Проверочный критерий (регрессионный):** прогон `loadgen` с дефолтным фильтром не содержит
  `Failed to send request` / `ERROR`. Проверяется ручными прогонами (см. `report.md`), т.к. требует
  in-process кластера + Redis.
- `tests/api`/`tests/cluster` не затронуты.
