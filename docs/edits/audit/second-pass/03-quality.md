## 3. Технические требования

- **Q1 (D10).** `/metrics` публичен и документирован как публичный, раскрывая term, индексы, число
  узлов, лидера. **Решено владельцем: оставляем публичным** (риск принят). Действий не требуется.
- **Q2 (C41).** `/pool` сортирует все узлы, `/full` обходит весь граф — оба под read-локом
  `state_machine`, что блокирует `apply` (write-лок). Считать по клону/снимку под коротким локом или
  ограничить объём.
- **Q3 (C42).** `HttpClient::new` при ошибке `Client::builder().build()` молча берёт `Client::new()`
  без таймаутов. Вернуть ошибку инициализации либо хотя бы явно залогировать уровень `warn!` с
  последствием (сейчас `error!`, но поведение всё равно тихо деградирует).
- **Q4 (C44).** Rate limit ключуется по `ConnectInfo`-IP; за прокси все клиенты делят ключ, без
  `ConnectInfo` — общий `"unknown"`. Учесть `X-Forwarded-For` по явно доверенной настройке либо
  документировать ограничение.
- **Q5 (D11, C39).** README упоминает `CLUSTER_NODES` (не используется) и не описывает
  `ADVERTISE_HOST`. Синхронизировать, `CLUSTER_NODES` удалить или задействовать. (S13 — расхождение
  AGENTS.md — уже исправлено владельцем.)
- **Q6 (D12).** OpenAPI `var.oneOf` предлагает «произвольные данные для неизвестных func», хотя
  `KNOWN_FUNCS` и SM принимают только `transferToken`. Привести схему к факту.
- **Q7 (S14).** Нет `.dockerignore`: build context тянет `target/`, `data/`, `logs/`, `.env`.
- **Q8.** Добавить регрессионные тесты: (а) отказ SM возвращает `4xx` через публичный путь (после K1);
  (б) два apply-прогона дают идентичные снапшоты (после V14); (в) `load-genesis` отвергает
  неканонический хэш (после K2).
