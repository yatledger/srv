# python/ — Python-нагрузчик `dagdb`

Внешний HTTP-клиент к **уже запущенному** кластеру `dagdb` (локальному или
удалённому). Кластер не поднимает — этим занимается Rust-инструмент (../docs/edits/feature/load-generator/) (`loadgen`, in-process). Python-версия
дополняет его и строит нагрузку по тем же правилам, что state machine:
канонический хэш/подпись (порт `src/utils.rs`), строго монотонный `seq` по адресу,
2..100 **живых** родителей из `/pool`.

## Установка

```bash
cd python
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
```

## Быстрый старт

```bash
# против локального узла на 21001
python -m loadgen

# против кластера из четырёх узлов
python -m loadgen --hosts http://127.0.0.1:21001 http://127.0.0.1:21002 \
  http://127.0.0.1:21003 http://127.0.0.1:21004 \
  --tx 500 --tps 200 --concurrency 8 --accounts 16 --seed 42

# с поиском лидера (внутренние ручки) и JSON-отчётом
INTERNAL_API_TOKEN=... python -m loadgen --internal-token "$INTERNAL_API_TOKEN" \
  --duration-sec 30 --tps 300 --json-out report.json
```

Код возврата: `0` — корректностные инварианты выполнены; `1` — нарушение
инварианта, недоступные узлы или ошибка параметров.

## Параметры

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `--hosts` | `http://127.0.0.1:21001` | адреса узлов кластера |
| `--tx` / `--duration-sec` | `500` | число транзакций **или** длительность (взаимоисключающе) |
| `--tps` | `500` | целевой суммарный TPS (`0` — без ограничения) |
| `--concurrency` | `8` | число конкурентных sender-задач |
| `--accounts` | `16` | число аккаунтов-отправителей |
| `--parents-min` / `--parents-max` | `2` / `8` | диапазон числа родителей (зажимается в `2..min(100,\|pool\|)`) |
| `--seed` | `1` | seed ГПСЧ (воспроизводимость параметров tx) |
| `--json-out` | — | путь JSON-отчёта |
| `--retry` | `10` | повторов на `429`/`503`/сетевую ошибку (backoff) |
| `--timeout` | `30` | таймаут HTTP-запроса, с |
| `--internal-token` | `$INTERNAL_API_TOKEN` | токен внутреннего API (поиск лидера) |
| `--verbose` | off | подробный вывод |

## Отчёт

Печатает: принято/отклонено с разбивкой по причинам, достигнутый TPS, перцентили
задержки `p50/p95/p99`, итоговый `total` из `/full` по каждому узлу.

**Корректностные инварианты (влияют на код возврата):** нет прикладных отказов у
заведомо валидных транзакций и одинаковый размер DAG на всех репликах.
Throughput и перцентили — информационные (без SLA).

JSON-отчёт:

```json
{
  "params": { "...": "..." },
  "accepted": 120,
  "attempted": 120,
  "rejected": [{ "reason": "...", "count": 1 }],
  "achieved_tps": 88.0,
  "latency_ms": { "p50": 40.5, "p95": 777.3, "p99": 793.8, "mean": 88.1, "max": 796.7 },
  "dag_total_per_node": { "http://host:port": 123 },
  "ok": true,
  "errors": []
}
```

## Тесты

```bash
cd python && pytest -q
```

Юнит-тесты: golden-вектор канонического хэша/подписи (сверен с `src/utils.rs`
побайтово), монотонность `seq` при параллельной выдаче, границы числа родителей,
детерминизм seed, правило `ok` и схема отчёта.

## Ключи и безопасность

> ⚠️ **Тестовые ключи.** `python/keys.py` содержит ключи дев-стенда и закоммичен
> **по решению владельца** — это осознанное отклонение от правила «секреты только
> из env» (`AGENTS.md` §4/§5). **Не используйте эти ключи в продуктивной среде.**

Переопределить набор без правки файла можно через окружение `LOADGEN_KEYS` —
JSON-массив объектов `{"sk": "...", "pk": "..."}` (base58).

## Ограничения

- Не поднимает кластер и не дублирует `N01`; работает внешним клиентом.
- Не поддерживает TLS (внутрикластерный/публичный трафик — как в проекте).
- Нет распределённой генерации с нескольких машин и измерения ресурсов узлов.
- Не входит в `cargo test --all` и не влияет на сборку Rust.
